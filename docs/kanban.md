# Workspace Kanban

`kanban.md` is the durable shared task board for named profiles and full OS worker processes. It coordinates work through Markdown rows that existing shared multi-dimensional table and Kanban utilities can parse. It is not a copied external board runtime, a browser-only store, an in-process subagent swarm, or a deploy mechanism.

## Owner and Allocation

`huijoohwee.github.io` owns this board and the [TODO contract](TODO.md). Canvas retains a routing link.
The [migration manifest](../todo/migration-agentic-canvas-os.json) preserves the prior board identity.
A named dispatcher owns changes to authored rows; workers supply evidence without concurrently
rewriting the shared board. Before assigning writes across devices, use the upstream
[fleet allocation contract](https://github.com/huijoohwee/agentic-os/blob/main/FLEET.md).
Board status and device labels never authenticate a remote claim or authorize an ownership transfer.

## Board Rules

| Rule | Requirement |
|---|---|
| Two table owners | `## Task Rows` is authored here and is the SSOT for live coordination. `## Ledger Projection` is generated by `scripts/kanban-projection.mjs` from the immutable ledger and must never be hand edited. |
| Projection is derived | Every projected cell comes from a recorded ledger cell or from the declared absent value. The projector invents no owner, priority, or progress. |
| Projection drift fails closed | `npm run planning:check` regenerates the fenced block and rejects any difference, row-count change, or digest change. Regenerate with `npm run kanban:project`. |
| Status vocabulary is split | Projected rows carry exactly `review`: the decision is recorded and immutable and its recommendation is outstanding. `backlog`, `ready`, `doing`, `blocked`, and `done` belong to authored rows, because the ledger records no work-progress state. |
| Projection scope | Only the ledger `active_period` projects. Legacy monthly shards stay history; projecting them would breach this file's own line budget. |
| Row SSOT | Every authored task, handoff, and sync state is a row in this file. Ledger-recorded planning decisions stay owned by `todo/<period>/<context>.md`. |
| Named profiles | `owner_profile` and `target_profile` must name explicit profiles or `none`. |
| Full worker process | `worker_process` names an OS process, terminal, or `none`; hidden subagents are not workers. |
| Context refs | `context_refs` uses bounded references such as `@file:`, `@diff`, or local source ids; unsafe refs remain blocked by `@reference-policy`. |
| Shared utilities | Projection uses existing multi-dimensional table and Kanban utilities; no duplicate parser or board datastore. |
| Conflict handling | Concurrent edits preserve evidence and require explicit `/kanban.sync` resolution. |

## Handoff Contract

| Field | Required meaning |
|---|---|
| `id` | Stable task or handoff id. |
| `type` | `task`, `handoff`, or `sync`. |
| `status` | One of the frontmatter `row_statuses`. |
| `owner_profile` | Current responsible named profile. |
| `worker_process` | Full OS process identity or `none`. |
| `target_profile` | Receiving profile for handoffs or `none`. |
| `context_refs` | Bounded references needed to continue. |
| `acceptance` | Observable completion condition. |
| `evidence` | Proof already produced. |
| `next_action` | Smallest concrete continuation step. |

## VCCs

| VCC | Check |
|---|---|
| Board parses | Frontmatter parses and task table contains required columns. |
| Rows are durable | Task and handoff state is stored in Markdown rows, not process memory. |
| Profiles are named | Owner and target profiles are explicit or `none`. |
| Workers are isolated | Worker processes have identity, cwd/command outside this file, proof, bounds, and cleanup when launched. |
| Deploy boundary holds | Board edits do not mutate Prod mirror or deploy Cloudflare. |
