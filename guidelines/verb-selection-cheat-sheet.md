# Verb‑selection Cheat Sheet

## Context 

**Documentation verbs**: consistent phrasing | neutral tone | context‑aligned actions | avoid repetition | structured guide | clarity | domain‑agnostic | actionable standards

## Intent 

**Documentation verbs**: Add new features | Support formats | Enable functionality | Provide resources | Showcase demos | Implement heuristics | Maintain stability | Refactor code | Render visuals | Evaluate tools | Unify documents | Prevent anti‑patterns | Ensure resilience | Make configurations

---

## 📘 Verb‑Selection Cheat Sheet

| **Verb**      | **Context / When to Apply**                                                                 | **Example One‑liner**                                                                 |
|---------------|---------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------|
| **Add**       | Introduce a new capability, feature, or option                                              | *Add semantic parsing mode as default; provide document‑structure mode as fallback.*   |
| **Support**   | Extend compatibility for formats, inputs, or platforms                                      | *Support HTML import for extended format coverage.*                                   |
| **Enable**    | Activate functionality or make a feature available                                          | *Enable sprint workflows with clear acceptance criteria.*                             |
| **Provide**   | Offer a resource, demo, or simplified version                                               | *Provide demo repo for interactive trial without installation.*                       |
| **Showcase**  | Highlight or demonstrate functionality in a neutral way                                     | *Showcase public demo repo; keep implementation private.*                             |
| **Implement** | Introduce a mechanism, heuristic, or algorithm                                              | *Implement generic heuristic for normalization.*                                      |
| **Maintain**  | Preserve existing functionality or stability                                                | *Maintain functionality with neutral, config‑driven approach.*                        |
| **Refactor**  | Restructure code or logic without changing behavior                                         | *Refactor URL rewriting logic from nodes.ts into helpers.ts.*                         |
| **Render**    | Visualize or display content (e.g., images, UI elements)                                    | *Render images as panel‑like rectangular nodes; link images as fallback.*             |
| **Evaluate**  | Assess tools, automation, or approaches                                                     | *Evaluate Git subtree split/CI/CD automation.*                                        |
| **Unify**     | Merge or consolidate multiple inputs or documents                                           | *Unify multiple documents at orchestration stage.*                                    |
| **Prevent**   | Explicitly block anti‑patterns or risks                                                     | *Prevent synchronous coupling and single points of failure.*                          |
| **Ensure**    | Guarantee a property such as resilience, consistency, or security                           | *Ensure system resilience through graceful degradation and circuit breakers.*         |
| **Make**      | Configure or adjust patterns, thresholds, or parameters                                     | *Make patterns configurable for adaptability.*                                        |

---

### 🔑 Guideline
- **Add / Support / Enable / Provide / Showcase** → outward‑facing, user‑visible changes.  
- **Implement / Maintain / Refactor / Render / Evaluate / Unify** → internal system or code changes.  
- **Prevent / Ensure / Make** → governance, safeguards, and configuration directives.
